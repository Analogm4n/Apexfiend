## 2. Host Migration

**The entire AD CS service has been migrated from `CA01` to a new host, `CA02`, including all templates and configuration.** The CA's own logical/AD object name remains `corp-CA01-CA` — this is the identifier published in `CN=Enrollment Services,CN=Public Key Services,...` and referenced throughout certificate templates; it did not change with the host migration. Earlier documentation elsewhere in this project (`01-architecture/`, `02-active-directory/`) refers to `CA01` at `172.16.50.100` — that address is now stale; `172.16.50.103` is current. The operator is reconciling earlier documents manually.

## 4. Enrollment Service Object

```powershell
Get-ADObject -LDAPFilter "(objectClass=pKIEnrollmentService)" -SearchBase "CN=Enrollment Services,CN=Public Key Services,CN=Services,$ConfigNC" -Properties dNSHostName, certificateTemplates
```

```text
Name:                 corp-CA01-CA
DistinguishedName:    CN=corp-CA01-CA,CN=Enrollment Services,CN=Public Key Services,CN=Services,CN=Configuration,DC=apexfiend,DC=lab
dNSHostName:           CA02.corp.apexfiend.lab
```

The enrollment service object lives in the **forest-wide Configuration partition** (`DC=apexfiend,DC=lab`, the root domain), not under `corp.apexfiend.lab` — standard AD CS behavior regardless of which domain the CA server itself is joined to.

## 6. CA Object ACL

```powershell
Get-Acl "AD:\CN=corp-CA01-CA,CN=Enrollment Services,CN=Public Key Services,CN=Services,$ConfigNC"
```

| Identity | Rights |
|---|---|
| `NT AUTHORITY\Authenticated Users` | GenericRead; **Enroll** (ExtendedRight) |
| `APEXFIEND\Enterprise Admins` | Full control |
| `CORP\CA02$` | Full control (the CA computer object itself) |
| `APEXFIEND\Domain Admins` | Full control (inherited) |

**The CA object itself grants `Enroll` broadly to `Authenticated Users`.** This does not, by itself, grant certificate issuance — the per-template ACL (`certificate-templates.md`) is the actual gate for which identities can request which certificate type. It does mean the CA-level control is not a meaningful restriction in this environment; template-level ACLs are where access is actually differentiated.
